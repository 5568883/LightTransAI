# 鲤桥翻译 (LightTransAI)

Windows 轻量级桌面翻译工具。C++20 + 原生 Win32 + Direct2D/DirectWrite + WIC + WinHTTP + DPAPI，无任何重型第三方依赖。

> 最后更新：2026-10-16（含悬浮按钮定位改造、应用图标、设置保存提示修复、内存口径更正）

### 功能开关现状

三个功能各自有独立开关（设置窗口 → 功能开关），且**开关真正生效**：

| 功能 | 默认 | 关闭后的行为 |

| 功能三：原位置覆盖 | **关** | 不注册 `Alt+W`（该功能尚未实现，开启也只会走框选+识别，不会画出覆盖层） |

**功能一的触发方式**是独立的三选一（设置窗口 → 功能一触发方式）：

| 取值 | 含义 |
|---|---|
| 快捷键 + 悬浮按钮（默认） | 两条通道都可用 |
| 仅快捷键 | **完全不安装全局鼠标钩子** —— 担心影响游戏或反作弊时选它 |
| 仅悬浮按钮 | 不注册 `Alt+E` |

### 重要：程序必须放在此目录运行

项目位于 **`D:\LightTransAI`**，**不要**从 `D:\deepseek工作区\` 下运行。

原因：AI 助手的工作区会给其中创建的所有文件打上 **Low（低）完整性** 标签，
Windows 会让进程继承该标签，导致：

- `SendInput` 注入的 Ctrl+C 被 UIPI 静默丢弃 → 取词失败
- `Shell_NotifyIcon` 返回错误码 5 → 托盘图标无法创建
- `%APPDATA%` 不可写 → 配置与日志落到程序目录

这些现象与代码无关，纯粹是运行环境的完整性级别限制。

## 二、构建

### 方式一：build.ps1（当前已验证可用）

```powershell
cd LightTransAI

pwsh -File .\build.ps1                 # Release
pwsh -File .\build.ps1 -Config Debug   # Debug
pwsh -File .\build.ps1 -Test           # 构建并运行单元测试
pwsh -File .\build.ps1 -Clean          # 删掉输出目录后重建
pwsh -File .\build.ps1 -Slim           # 构建后清中间产物，只留 exe
```

产物：`build\Release\LightTransAI.exe`（约 **700 KB**，静态链接 CRT，**无需分发任何 DLL**）

同时会**自动在工程根目录放一份 `鲤桥翻译.exe`**（仅 Release），方便直接双击或拷给别人：

```
D:\LightTransAI\
├── 鲤桥翻译.exe                    ← 好找的入口，构建时自动同步
├── build\Release\LightTransAI.exe  ← 真正的链接产物
└── ...
```

> 两者内容完全相同（可对比 SHA256）。根目录那份是**拷贝**而不是快捷方式 ——
> 快捷方式在 `build` 目录被 `-Clean` 清掉后会失效，而拷贝出来的文件随时可用、
> 也能直接发给别人。
>
> 只对 Release 做同步：Debug 版依赖调试环境，且与 Release 同名会冲突，
> 容易让人误运行到慢速的调试版。
>
> 若程序正在运行，根目录那份会因文件被占用而拷贝失败；此时脚本给出提示
> 而**不中断构建**，退出程序后重新构建即可。

脚本会自动通过 `vswhere` 定位 Visual Studio 并导入 MSVC 环境，无需手动开 "Developer Command Prompt"。

#### 关于磁盘占用（重要）

`build` 目录的中间产物合计可达 **180 MB 以上**，但**全是可再生的**，删掉不影响运行：

| 类型 | 典型大小 | 说明 |
|---|---|---|
| `.obj` | ~86 MB | 每个 .cpp 的机器码中间件 |
| `.pdb` | ~52 MB | 调试符号（仅 Debug 构建产生） |
| `.ilk` | ~38 MB | 增量链接缓存 |

`.obj` 偏大的原因是 **`nlohmann/json` 的模板在 3 个 cpp 里各实例化一遍**
（`ai_vision_provider.obj` / `config_manager.obj` / `deepseek_client.obj` 各约 6.8 MB）。
实测 `/Gy` + `/Zc:inline` **无任何效果**；但**链接器已去重，最终 exe 不受影响**。
若想根治需把 JSON 处理收进单一编译单元，收益仅在编译时间与磁盘。

平时用 `-Slim` 即可把 `build` 从 62 MB 降到 7.5 MB。

## 三、已实现功能（阶段二）

### 主窗口（任务栏可见入口）

程序启动后显示一个主窗口，提供全部操作入口：打开设置、功能二/三入口、
实时内存显示、退出程序。

**关闭行为取决于托盘是否可用：**

| 托盘状态 | 关闭主窗口的行为 |
|---|---|
| 可用 | 收起到托盘，程序继续后台运行 |
| 不可用 | **直接退出程序**（否则程序将失去所有入口，只能杀进程） |

> **关于"零常驻界面"的偏离**：规范要求除隐藏消息窗口与托盘外不创建任何 GUI 窗口。
> 实测中托盘在受限环境（低完整性级别、任务栏未运行）下会创建失败，
> 此时用户面对一个"没图标、没窗口、没报错"的进程，完全无从下手。
> 因此增加主窗口作为可靠入口。

### 功能一：划词悬浮翻译

1. 在任意可选择文字的软件中选中文字
2. **主触发**：划词松开鼠标后，在**选区末尾右侧**弹出「译 翻译」胶囊按钮
   - **位置**：以鼠标松开点（= 选区末尾）为锚点，右侧 8px、垂直精确居中；
     若右侧放不下（选区贴屏幕右缘）则**自动翻到左侧**，而不是贴住边缘盖住文字
   - 点击即翻译；3 秒无操作、点击别处、滚动滚轮或按键则自动销毁
   - 按钮带 `WS_EX_NOACTIVATE`，**不抢焦点**，原软件选中的蓝色高亮不会消失
3. **备用触发**：选中文字后按 `Alt + E` 直接翻译
4. 弹窗显示「DeepSeek 翻译中……」，完成后只显示中文译文
5. 支持「复制译文」、「×」关闭、`Esc` 关闭、滚轮滚动

#### 悬浮按钮的两个实现要点（都是踩过的坑）

**① 分层窗口必须主动绘制，不能只等 `WM_PAINT`**

按钮用 `WS_EX_LAYERED` + `UpdateLayeredWindow` 呈现逐像素 alpha（投影与圆角需要）。
分层窗口的内容由 `UpdateLayeredWindow` 直接提交，**系统不保证在 `ShowWindow` 后派发
`WM_PAINT`** —— 结果是一个位置正确但完全透明的空白窗口。
因此 `Show()` 末尾必须主动调用一次 `Paint()`。

**② 分层窗口不能用 `ApplyDwmRoundCorners`**

DWM 的圆角/描边处理会按**窗口矩形**再画一层不透明的底。窗口比胶囊大一圈
（四周各 9px 投影留白），于是胶囊外面会出现一个**白色方框**。
两套圆角机制必须只留一套：分层窗口只用 Direct2D 自绘。

**③ 点击别处要撤销，必须靠钩子事件而不是轮询**

原先依赖 120ms 定时器轮询 `GetAsyncKeyState`，但一次快速点击（按下+抬起）
完全可能落在两次轮询之间，按钮会赖在屏幕上直到 3 秒超时。
现改为鼠标钩子在 `WM_LBUTTONDOWN` 时投递 `WM_LT_MOUSE_DOWN`（带坐标），
由 UI 线程做命中判断：点在按钮外 → 立即撤销；点在按钮上 → 不撤销（那正是要翻译）。
钩子回调内只做一次 `new` + `PostMessage`，满足 300ms 时限约束。

### 功能二：框选屏幕翻译（Alt + Q）

1. 按 `Alt + Q`
2. **屏幕瞬间冻结**，覆盖半透明暗色遮罩与十字光标
3. 按住鼠标左键拖拽框选区域
   - 选区内部保持原亮度，外部压暗，便于对准
   - 白色边框标示当前选区
4. 松开鼠标后立即关闭遮罩，在选区附近弹出翻译窗口
5. 窗口只显示中文译文，支持「复制译文」、`×`、`Esc` 关闭

**取消方式**：`Esc`、鼠标右键或中键；选区宽或高 **小于 10 像素**视为误触自动取消。

**实现要点**：

- **冻结画面裁图**：选区从触发瞬间冻结的屏幕位图裁出，而不是等遮罩关闭后
  重新抓屏 —— 后者会因底层窗口重绘/滚动导致画面与用户所见不一致
- **整屏呈现用 `UpdateLayeredWindow`**：一次呈现，无闪烁
- **遮罩不抢焦点**（`WS_EX_NOACTIVATE`），`Esc` 由低级键盘钩子捕获
- **JPEG 质量不省 token**：官方按图片像素计费（每图上限 1024 token），
  与文件体积无关。因此质量取 92 保证 OCR 准确率，
  靠**缩放尺寸**（最长边 1600）控制 token

> ⚠ **必须带 `WS_EX_LAYERED`**：`UpdateLayeredWindow` 要求窗口具有此扩展样式，
> 否则调用**静默失败**（返回 `ERROR_INVALID_PARAMETER`），画面什么都不显示。
> 这个坑极隐蔽：鼠标消息仍能正常收到，所以**框选逻辑全部工作、测试全部通过，
> 但用户看不到任何遮罩与拖拽框**。现已补上样式并增加返回值检查与日志。

> ⚠ **视觉线程必须自己 `CoInitializeEx`**：COM 初始化是**线程私有**的，
> 主线程初始化对别的线程无效。JPEG 编码跑在后台线程，若不初始化 COM，
> `CoCreateInstance(CLSID_WICImagingFactory)` 会返回 `CO_E_NOTINITIALIZED`。
> 更糟的是 `WicFactory()` 的 `static` 单例会把 `nullptr` **永久缓存**，
> 表现为"一旦编码失败，之后每次都失败"。现已在该线程初始化 COM，
> 且 `WicFactory()` 改为**只在成功时缓存**。

### 系统托盘

右键菜单（全简体中文）：打开设置 / 功能一开关 / 功能二 / 功能三 / 内存占用状态 / 退出。

托盘图标**优先读取 exe 内嵌的多尺寸图标资源**（`LoadImage` 自动挑选最接近的尺寸帧），
因此托盘、任务栏、开始菜单里的图标完全一致；资源缺失时才退回代码绘制。

### 设置窗口

- DeepSeek API 地址、Key（密码框）、模型名称 + **测试连接**
- 视觉模型独立配置（可选，不填则复用 DeepSeek）
- **功能开关**：功能一/二/三各一个启用勾选框 + 功能一触发方式下拉
- **快捷键**：三个热键输入框，保存后**立即重新注册**（无需重启）
  - 输入会做校验：单个字母（会抢走所有程序按键）、系统保留组合（`Alt+F4`/`Alt+Tab`）、
    两个热键重复、格式残缺 —— 均给出中文提示并拒绝保存
  - 支持大小写不敏感与全角 `＋`
- 识别模式下拉框、保存设置

> **窗口高度由内容决定，不是写死的常量**：`CreateControls()` 会把内容总高度算出来，
> 窗口据此定高。之前是手写常量，加"功能开关"区时算少了 22px，

配置与日志位置（自动选择第一个可写目录）：

1. `%APPDATA%\LightTransAI\`
2. `程序目录\LightTransAI_data\`（便携模式 / `%APPDATA%` 受限时）
3. `%TEMP%\LightTransAI\`

> 目录名保持 `LightTransAI` 不变（产品显示名已改为「鲤桥翻译」）：
> 改目录名会让用户已保存的 API Key（DPAPI 密文）找不到。

## 四、相对原始规范的重要修正

开发过程中依据 **2026-09 官方文档** 与实际编译测试，对规范做了以下修正：

### 1. 模型名称（阻断性）

- 规范默认的 `deepseek-chat` **已于 2026-07-24 下线**，直接使用会报错
- 现改为 **`deepseek-flash`**（当前可用模型：`deepseek-flash` / `deepseek-v4-pro`）
- `deepseek-flash` **原生支持视觉输入**（`image_url` + base64），
  因此一套 API Key 即可同时支撑功能一、二、三，配置大幅简化

### 2. 必须显式关闭思考模式（阻断性）

官方 `thinking.type` **默认为 `enabled`**。翻译是确定性任务，开启思考只会
显著增加延迟与 token 消耗。已显式设置 `thinking: {"type": "disabled"}`。

### 3. 编译选项（阻断性）

- **`/utf-8` 必需**：源码含中文注释与字符串，在 GBK 代码页下会编译失败
  （实测报 C4819 与大量"未声明标识符"）
- **`/Zc:__cplusplus` 必需**：否则 `__cplusplus` 恒为 `199711`
- **不可定义 `WIN32_LEAN_AND_MEAN`**：它会让 `windows.h` 不再包含 `unknwn.h`，
  导致 `UIAutomation.h` 接口声明缺少 `IUnknown` 基类而编译失败

### 4. 划词判定改为 UIA 正信号优先

规范用 `hCursor == IDC_IBEAM` 判定，但：

- 很多应用（Electron、自绘控件）用 `CopyCursor` 产生自定义句柄，判定永远为假
- 反之，光标是 IBeam 也不代表有选中文字（悬停时也是）

现改为：**UIA 是否探测到非空选区**作为主判据（正信号，且不触碰剪贴板），
工字光标仅作辅助。

### 5. 剪贴板改为"尽力还原"

规范所称"无损"在技术上无法达成：`CF_HDROP`、HTML/RTF 的延迟渲染数据无法
忠实备份还原，写回也会改变剪贴板属主。现实现为**尽力还原**（文本 + 文件列表），
并明确记录未能完全还原的情况。

### 6. 控制台保护

向 `Windows Terminal` / `cmd` 发送 `Ctrl+C` 会被解释为 **SIGINT**，
可能打断用户正在运行的程序。现对控制台类窗口**直接跳过剪贴板通道**并给出提示。

### 7. 线程与钩子约束

- **UIA 调用一律在工作线程**：跨进程 COM 调用遇到繁忙应用可能阻塞数百毫秒，
  绝不可放在钩子回调或 UI 线程裸调
- **低级钩子回调内只做 PostMessage**：超过 `LowLevelHooksTimeout`（默认 300ms）
  会被 Windows **静默摘除**
- 划词探测有并发闸门，防止快速连续划词导致线程堆积

### 8. Esc 键捕获

翻译弹窗与覆盖层带 `WS_EX_NOACTIVATE`（不抢焦点），因此 `Esc` 不会自动送达。
现通过 `WH_KEYBOARD_LL` 低级键盘钩子捕获，**按需安装、用完立即卸载**。

### 9. 内存回收策略（附：指标口径的重要更正）

`SetProcessWorkingSetSize(-1,-1)` 只把页面移到备用列表，**私有提交量不会下降**，
且下次唤醒需硬缺页。因此**只在真正空闲后延迟调用**，避免拖慢下一次翻译的首次响应。

另新增 `PerfMonitor::ReleaseFreeHeap()`（内部调 `_heapmin()`），
让 CRT 堆把完全空闲的段真正还给系统。框选结束后立即调用，
使专用工作集从 22 MB 回落到 **5.9 MB**。

> ⚠ **不要用「提交大小」（`PrivateMemorySize64`）衡量本程序的内存占用。**
> 这个指标被系统映射严重污染：实测本程序闲置时
> 「提交 8.85 MB」而「专用工作集仅 7.00 MB」，其中真正的**私有内存只有 0.75 MB**，
> 其余是 Windows 自己映射进来的**共享只读数据**：
>
> | 映射文件 | 大小 | 归属 |
> |---|---|---|
> | `StaticCache.dat` | 19.25 MB | Windows 全局字体缓存 |
> | `~FontCache-FontFace.dat` | 16.00 MB | Windows 字体缓存 |
> | `~FontCache-S-1-5-21-...dat` | 8.00 MB | 当前用户字体缓存 |
> | `SortDefault.nls` / `locale.nls` | 4.27 MB | 系统区域/排序表 |
>
> 这些是 **Windows 自己映射的**，任何用 DirectWrite 的程序都会拉起，
> 且多个程序**共享同一份物理内存**。对照参照物：记事本「提交 127 MB」
> 但专用工作集只有 2.25 MB。
>
> **正确口径是「专用工作集」（`Working Set - Private`）**，对应性能计数器
> `\Process(名)\Working Set - Private`。

### 10. 悬浮按钮的撤销通路（规范要求补齐）

规范要求悬浮按钮在"点击别处、滚动滚轮、按键或超过 3 秒"时自动销毁。
实现上分了四条独立通路：

- **鼠标点击**：鼠标钩子投递 `WM_LT_MOUSE_DOWN`（带坐标），**事件驱动、不漏**
- **滚轮**：鼠标钩子的 `WM_MOUSEWHEEL` 投递 `WM_LT_MOUSE_ACTIVITY`
- **按键**：键盘钩子的 `WM_KEYDOWN` 投递 `WM_LT_CANCEL_REQUEST(kCancelAnyKey)`
- **超时**：`TIMER_FLOATBTN_EXPIRE` 3 秒

> 鼠标点击**曾经**靠 `TIMER_FLOATBTN_WATCH` 每 120ms 轮询 `GetAsyncKeyState`，
> 但快速点击（按下+抬起）可能完全落在两次轮询之间，按钮会赖在屏幕上直到 3 秒超时。
> 现改为钩子事件驱动；那个轮询保留作兜底（万一钩子未安装）。

两处细节：
- 滚轮通知**仅在按钮可见期间开启**。否则用户每次滚动都会产生一次
  `new POINT` + `PostMessage`，是无谓的常态开销。
- "任意按键"只撤销悬浮按钮，**不会**顺带关掉翻译弹窗（两者语义不同）。

### 11. 键盘钩子按需装卸

键盘钩子并非全程常驻：悬浮按钮或翻译弹窗出现时安装，两者都消失后立即卸载
（`ReleaseEscHookIfIdle`）。钩子常驻会带来无谓的系统开销。

### 12. TLS / 证书错误的中文可操作提示

企业网络的代理常做 TLS 中间人检查并替换证书，导致 `ERROR_WINHTTP_SECURE_FAILURE`、
`ERROR_WINHTTP_CLIENT_CERT_NO_PRIVATE_KEY` 等错误。这些在真实环境中很常见，
现已给出"若在公司网络下可能是代理证书检查所致，请尝试更换网络"之类的
可操作中文指引，而不是抛一个裸错误码。

在开发机（Windows 11 Build 26300，2560×1440）实测：

| 指标 | 规范目标 | 实测 | 结果 |
|---|---|---|---|
| 闲置专用工作集 | < 10 MB | **7.00 MB** | ✅ 达标 |

| 可执行文件体积 | — | **700 KB** | — |

### 内存轨迹（准确口径）

| 状态 | 专用工作集（真实占用） | 提交大小 |
|---|---|---|
| 启动闲置 | **7.00 MB**（连读 3 次稳定） | 8.85 MB |
| 第 1 次框选翻译后 | 22.20 MB | 46.25 MB |
| 第 2 次 | **6.00 MB** | 46.70 MB |
| 第 3 次 | **5.86 MB** | 46.64 MB |

**不是内存泄漏**：第 2、3 次只涨 0.3 MB 以内，且专用工作集稳定回落到约 6 MB。

**提交量 46 MB 降不下来的原因**：框选流程会临时申请两块全屏缓冲
（冻结画面 + 遮罩 DIB，各 `2560×1440×4` ≈ 14.7 MB）。
`CreateDIBSection` 分配的是**内核段对象**，`_heapmin()` 管不到；
而且这些页面大部分未被触碰/已换出，**实际只驻留约 6 MB 物理内存**。

> 若日后要让"提交大小"也好看，唯一有效的办法是把冻结画面改为**分条带处理**
> （用一条 `2560×64` 的小缓冲逐段渲染遮罩），峰值可从 29 MB 降到约 1 MB。
> 代价是遮罩渲染改成块循环，且每次鼠标移动要重绘全部条带，需实测帧率。

## 八、已知限制

1. **托盘图标在无 `explorer.exe` 的环境下会创建失败**（如某些自动化会话）。
   程序已优雅降级为后台运行并记录日志，不影响其它功能。
2. **`Alt+E` / `Alt+Q` / `Alt+W` 会抢占目标程序的同名快捷键**。
   `RegisterHotKey` 是全局优先的，例如 `Alt+E` 会让许多软件的「编辑(E)」菜单失效。
   注册失败时会给出明确中文提示，可在设置中改用其它组合。
3. **DPAPI 绑定当前 Windows 用户**。换账户或换机器后 Key 无法解密，
   程序会提示「请重新输入」而不是崩溃。
4. **功能三（原位置覆盖）尚未实现**。开关默认关闭；即使打开也只会走
   "框选 → 识别"，**不会在屏幕上画出覆盖层**。设置里已明确标注这一点，
   避免用户以为程序坏了。
5. 跨不同 DPI 显示器的框选区域需要拆分为多个覆盖层，将在阶段四处理。
6. **全局鼠标钩子**（为划词悬浮按钮服务）会给每次鼠标事件加一跳。
   若担心影响游戏或被反作弊误判，在设置里把功能一触发方式改为
   **「仅快捷键」** —— 程序将完全不安装该钩子。
